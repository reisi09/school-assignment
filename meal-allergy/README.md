# 급식 알레르기

학교 급식 식단의 알레르기 번호를 내 알레르기와 비교해 알려 주는 Streamlit 서비스입니다. 고색고 응용 프로그래밍 개발 개인 프로젝트 수행평가로 만들었으며, 이전 학교한눈에서 급식 알레르기 확인에 집중하도록 바꿨습니다.

## 왜 만들었나

식단표는 메뉴 뒤에 `5.6.10.13` 같은 번호로 알레르기 식품을 알려 주므로 번호표를 매번 대조해야 합니다. [KBS 뉴스9의 2026년 7월 24일 보도](https://news.kbs.co.kr/news/view.do?ncd=8619797)에 따르면 식단표에 의무 표기되는 견과류는 땅콩·호두·잣 3종뿐입니다. 같은 보도에서는 지난해 보고된 아나필락시스 환자 1,800여 명의 대다수가 영유아와 10대 청소년이라고 전했습니다. 식단에 적힌 번호를 내 알레르기와 쉽게 비교하려고 만들었습니다. 아몬드·캐슈넛처럼 번호가 없는 재료는 `주의 낱말`로 등록해 메뉴 이름에서 찾습니다. 이름에 드러나지 않은 성분까지 알아낼 수는 없습니다.

## 화면 안내

로그인하지 않아도 기본 학교인 고색고등학교 급식을 볼 수 있습니다. 내 알레르기 표시는 로그인한 뒤 알레르기를 저장해야 나옵니다. 위쪽 메뉴 오른쪽에는 로그인 전에는 `로그인` 하나, 로그인 뒤에는 `내 설정`과 `로그아웃`이 보입니다.

| `로그인` 창 | `로그인`·`회원가입`·`비밀번호 찾기` 탭이 있습니다. 로그인할 때는 아이디와 비밀번호를 입력하고 `로그인`을 누릅니다. 틀리면 둘 중 무엇이 틀렸는지 구분하지 않고 안내합니다. 회원가입할 때는 아이디(3~20자), 비밀번호(8자 이상), 비밀번호 확인을 입력하고 `가입하기`를 누릅니다. 같은 아이디로는 가입할 수 없으며, 가입하면 바로 로그인합니다. 처음 학교는 고색고등학교이고 알레르기는 없습니다. 세 번째 탭인 `비밀번호 찾기`에서는 아이디·복구 코드·새 비밀번호·새 비밀번호 확인을 입력하고 `비밀번호 바꾸기`를 누릅니다. 성공하면 바로 로그인합니다. 아이디가 없거나 복구 코드가 틀리면 같은 안내를 보여 줍니다. |
| `복구 코드` 창 | 가입 직후와 복구 코드로 비밀번호를 바꾼 직후에 새 코드를 한 번 보여 줍니다. `적어 두었습니다`를 눌러야 닫히며, 닫은 뒤에는 코드를 다시 볼 수 없습니다. 비밀번호를 바꿀 수 있는 코드이므로 따로 적어 두고 다른 사람에게 보여 주지 않습니다. |
| `내 설정` 창 | 로그인한 사람만 엽니다. 학교 이름을 입력하고 `학교 찾기`를 누른 뒤 학교를 고릅니다. `내 알레르기`를 여러 개 고르고 `내 설정 저장`을 누르면 내 계정에 저장합니다. 다른 기기에서도 같은 계정으로 로그인하면 저장한 학교와 알레르기를 씁니다. |

`오늘` 화면 맨 위에는 로그인 전에는 `로그인하고 내 알레르기를 등록하세요`와 `로그인` 버튼이 나옵니다. 로그인했지만 알레르기를 저장하지 않았다면 `내 알레르기를 등록하세요`와 `내 설정 열기` 버튼이 나옵니다. 알레르기까지 저장하면 이 안내 카드는 사라집니다. 로그인 뒤 학교 이름 줄에는 `고색고등학교 · 아이디님`처럼 학교와 아이디가 함께 나옵니다. `내 알레르기` 카드도 로그인 전에는 로그인 안내와 `로그인` 버튼을 보여 줍니다.

| 조회 | 주의 낱말: `watch_words` | `내 주의 낱말`에서 내 계정의 낱말과 메모를 등록한 순서대로 봅니다. |
| 수정 | 내 설정: `users` | 로그인한 뒤 `내 설정`에서 학교와 알레르기를 고르고 `내 설정 저장`을 누릅니다. 내 계정의 설정만 바꿉니다. |

| 검색 | 학교 | `내 설정`의 `학교 찾기`에서 학교 이름으로 찾습니다. 결과에는 학교 이름과 주소를 함께 표시합니다. |

급식 검색은 현재 선택한 학교의 저장된 기록 전체를 대상으로 합니다. 예전에 저장한 기록은 오늘 앞뒤 28일을 벗어나도 검색하며, 최근 날짜부터 보여 줍니다. 나이스 연결에 실패해도 이미 저장된 기록에서는 검색합니다. `오늘`과 `급식표`를 보는 것만으로는 급식 기록을 DB에 저장하지 않습니다.

## 알레르기를 알아내는 방법

나이스의 메뉴 글자는 `<br/>`로 이어져 있습니다. `foods.py`의 `parse_dishes`가 줄을 나누고, `parse_dish`가 각 줄 끝의 숫자 괄호를 메뉴 이름과 분리합니다. 이름 안의 `(수제)` 같은 괄호는 남깁니다.

```python
from foods import find_my_allergens, parse_dish

parse_dish("돈육한방수육 (5.6.10.13)")
# ("돈육한방수육", [5, 6, 10, 13])

parse_dish("김치함박스테이크(수제) (2.5.6)")
# ("김치함박스테이크(수제)", [2, 5, 6])

find_my_allergens([5, 6, 10, 13], [10, 5])
# ["대두", "돼지고기"]
```

`find_my_allergens`는 메뉴 번호와 내 알레르기 번호가 겹치는 식품의 이름을 돌려줍니다. `screen_meal.py`의 `dishes_html`은 해당 메뉴를 빨갛게 표시하고 식품 이름을 붙입니다. `count_risky_dishes`는 해당 메뉴 수를 셉니다.

`common.py`의 `my_words(profile)`는 로그인한 사람의 주의 낱말 목록을 돌려주며, 로그인 전에는 빈 목록을 돌려줍니다. `foods.py`의 `find_watch_words(name, words)`는 메뉴 이름과 주의 낱말에서 띄어쓰기를 빼고 낱말이 이름에 들어 있는지 비교합니다. 예를 들어 `아몬드`를 등록하면 `아몬드 쿠키`를 찾습니다.

`dishes_html(dishes, my_codes, words)`는 주의 낱말이 든 메뉴 이름을 굵게 하고 남색 알약 모양의 `주의 낱말 · 아몬드` 표시를 붙입니다. `오늘`·`급식표`·`찾기` 화면에 같은 방법으로 표시하며, 내 알레르기 번호도 겹치면 빨간 알레르기 표시를 함께 붙입니다. 주의 낱말은 `count_risky_dishes`가 세는 내 알레르기 메뉴 수에는 더하지 않습니다.

번호와 식품 이름은 `foods.py`의 `ALLERGENS`에 다음과 같이 들어 있습니다.

| 번호 | 식품 | 번호 | 식품 |
| --- | --- | --- | --- |
| 1 | 난류 | 11 | 복숭아 |
| 2 | 우유 | 12 | 토마토 |
| 3 | 메밀 | 13 | 아황산류 |
| 4 | 땅콩 | 14 | 호두 |
| 5 | 대두 | 15 | 닭고기 |
| 6 | 밀 | 16 | 쇠고기 |
| 7 | 고등어 | 17 | 오징어 |
| 8 | 게 | 18 | 조개류 |
| 9 | 새우 | 19 | 잣 |
| 10 | 돼지고기 | — | — |

학교가 식단에 표시한 알레르기 번호와 메뉴 이름에 든 주의 낱말만 비교합니다. 메뉴 이름에 재료가 드러나지 않으면 주의 낱말로도 찾을 수 없습니다. 표시되지 않은 성분·교차오염·개인별 민감도는 알 수 없습니다. `내 알레르기 메뉴 없음`이나 주의 낱말 표시가 없는 메뉴도 안전하게 먹어도 된다는 뜻은 아닙니다. 참고용이며 의학적 판단을 대신하지 않으므로 먹기 전에 영양 선생님께 확인해야 합니다.

## 쓴 자료 (API)

학교 자료는 [나이스 교육정보 개방 포털](https://open.neis.go.kr)의 공개 API에서 받습니다. `neis.py`의 요청 주소는 `https://open.neis.go.kr/hub/`입니다.

| 자료 | API 이름 | 앱에서 쓰는 내용 |
| --- | --- | --- |
| 학교 기본 정보 | `schoolInfo` | 학교 이름·종류·교육청 코드·학교 코드·주소로 학교를 찾습니다. |
| 급식 | `mealServiceDietInfo` | 날짜·끼니·메뉴·알레르기 번호·열량·영양 정보·원산지·급식 인원을 받습니다. |
| 학사일정 | `SchoolSchedule` | 급식이 없는 날에 휴업일·공휴일의 행사 이름을 보여 줍니다. |

인증키 없이도 모든 기능을 사용할 수 있습니다. 다만 키가 없으면 한 번에 5건까지만 받습니다. `fetch_range`는 전체 기간을 먼저 요청하고, 덜 받으면 일주일씩 나눠 요청합니다. 그래도 다 받지 못한 주는 하루씩 나눠 받습니다.

학교 검색은 기간을 나눌 수 없으므로 키가 없으면 앞 5곳만 보여 줍니다. 결과가 더 많으면 학교 이름을 자세히 쓰라는 안내가 나옵니다. 하루 자료 자체가 5건을 넘는 경우에도 키 없이 전부 받는 것은 보장하지 않습니다.

`search_schools`, `fetch_meals`, `fetch_schedule`은 `st.cache_data(ttl=3600)`으로 받은 자료를 1시간 기억합니다. 같은 조건으로 다시 조회할 때는 저장해 둔 응답을 씁니다. 이 임시 저장과 SQLite의 급식 기록 저장은 별개입니다.

## 나이스 인증키(선택)

인증키를 넣으면 한 번에 최대 1,000건을 요청하므로 기간을 나눠 요청하는 횟수가 줄어듭니다. 나이스 교육정보 개방 포털에서 인증키를 발급받습니다.

로컬에서는 `app.py`가 있는 폴더 아래에 `.streamlit/secrets.toml`을 만들고 다음 줄을 넣습니다.

```toml
NEIS_KEY = "발급받은 키"
```

Streamlit Community Cloud에서는 앱의 Settings → Secrets에 같은 줄을 넣습니다. `.streamlit/secrets.toml`은 `.gitignore`에 있어 git에 올라가지 않습니다. 인증키는 코드에 적지 않습니다.

### 저장하는 자료와 함수

`connect_db`는 같은 폴더의 `meal_allergy.db`에 연결합니다. `create_tables`는 `users`·`watch_words`·`meals`를 만들며, 예전 버전의 테이블은 현재 구조에 맞게 고칩니다. 세 테이블에는 각각 10개·5개·6개, 모두 21개의 칸이 있습니다.

예전 `users`에 `recovery_hash`가 없으면 `ALTER TABLE`로 칸을 붙이고 빈 글자로 둡니다. 기존 계정은 그대로 로그인할 수 있지만 복구 코드가 없어 비밀번호 찾기를 쓸 수 없습니다. 예전 `meals`에 `saved_at`이 있으면 테이블을 지우고 새로 만듭니다. 이때 지워진 급식 기록은 나이스에서 다시 받으면 됩니다.

### 로그인과 비밀번호 저장

`database.py`의 `hash_password`는 원래 비밀번호 대신 해시를 만듭니다. 해시는 비밀번호를 확인할 때 쓰는 글자입니다. 계정마다 `secrets.token_hex(16)`으로 만든 무작위 글자인 소금(salt)을 섞으므로 같은 비밀번호라도 저장되는 글자가 다릅니다. `hashlib.pbkdf2_hmac("sha256", …, 200000)`으로 200,000번 반복해 계산하고 `소금$해시` 모양의 97자 글자를 저장합니다. 원래 비밀번호는 저장하지 않습니다.

`check_password`는 저장된 소금을 꺼내 입력한 비밀번호의 해시를 다시 만듭니다. 두 값을 비교할 때는 비교 시간으로 값을 짐작하기 어렵게 하는 `hmac.compare_digest`를 씁니다.

```python
from database import check_password, hash_password

stored = hash_password("password1")
# stored에는 원래 비밀번호 대신 "소금$해시" 모양의 글자가 들어갑니다.
check_password("password1", stored)  # True
check_password("password2", stored)  # False
```

회원가입할 때는 `make_recovery_code()`로 복구 코드를 만듭니다. 헷갈리기 쉬운 `0`·`O`·`1`·`I`를 뺀 대문자와 숫자 12글자이며, `K7QM-3XRP-9DTA`처럼 4글자씩 나눠 보여 줍니다. `create_user(username, password, password_confirm, school, recovery_code)`는 `hash_password(normalize_code(recovery_code))`의 결과만 `users.recovery_hash`에 저장합니다. `normalize_code`는 소문자를 대문자로 바꾸고 하이픈과 띄어쓰기를 빼므로 `k7qm3xrp9dta`로 입력해도 같은 코드로 봅니다.

비밀번호를 잊으면 `비밀번호 찾기` 탭에서 복구 코드로 새 비밀번호를 정합니다. `reset_password(username, recovery_code, new_password, new_password_confirm, new_recovery_code)`는 `check_new_password`로 새 비밀번호를 검사한 뒤 아이디와 복구 코드가 맞으면 두 해시를 함께 바꿉니다. 성공하면 `SUCCESS`, 8자보다 짧으면 `SHORT_PASSWORD`, 비밀번호 확인이 다르면 `MISMATCH`를 돌려줍니다. 아이디가 없거나 코드가 틀리면 모두 `WRONG_CODE`를 돌려주며 화면 안내도 같습니다. 쓴 코드는 다시 쓸 수 없으므로 새 코드를 보관해야 합니다.

가입이나 비밀번호 변경에 성공하면 `screen_account.py`가 바로 로그인하고 새 코드를 `st.session_state["recovery_code"]`에 잠깐 둡니다. `app.py`는 이 값이 있으면 `show_recovery_code`를 부릅니다. 이 창은 `st.dialog`의 `dismissible=False`로 만들었으므로 `적어 두었습니다`를 눌러야 닫힙니다. 버튼을 누르면 임시 코드도 지워져 다시 볼 수 없습니다.

로그인한 계정 정보는 `st.session_state["user"]`에 둡니다. `screen_account.py`의 `start_session`이 이 값을 넣고, `log_out`이 지웁니다. 새로고침하면 로그인 상태가 사라지므로 다시 로그인해야 합니다.

학교와 알레르기는 `save_settings(user_id, school, allergies)`가 `users`의 내 계정 줄에 저장합니다. 로그인 상태가 풀려도 DB에 저장한 설정은 남으며, 다른 기기에서도 같은 계정으로 로그인하면 그대로 씁니다.

## 실행 방법

`app.py`가 있는 폴더에서 다음 명령을 차례로 입력합니다.

## 알아 둘 점

- 비밀번호를 잊어도 복구 코드가 있으면 새로 정할 수 있습니다. 복구 코드까지 잃어버리면 계정을 되찾을 수 없습니다.
- 예전 버전에서 만든 계정은 복구 코드가 없습니다. 기존 비밀번호로 로그인할 수는 있지만 비밀번호 찾기는 쓸 수 없습니다.
- 새로고침하면 로그인이 풀립니다. 다시 로그인해야 저장한 학교와 알레르기를 쓸 수 있습니다.
- Streamlit Community Cloud에서 앱이 다시 시작되면 DB와 계정이 지워질 수 있습니다. 저장한 설정과 급식 기록이 계속 남는다고 보장하지 않습니다.
- 알레르기는 건강 정보이므로 아이디에 실명이나 개인을 알아볼 수 있는 정보를 쓰지 않습니다.
- `screen_meal.py`의 `empty_message`는 급식 자료가 없는 날짜가 오늘보다 뒤이고 학사일정의 쉬는 날 목록에도 없으면 `급식 자료 미등록`을 돌려줍니다. 그 밖에는 `급식 없음`을 돌려줍니다. 주간 화면은 월요일부터 금요일까지만 보여 주며, 쉬는 날 이름이 있으면 함께 표시합니다. 이 문구는 날짜와 학사일정으로 구분한 것이므로 실제 미등록 사유를 확인한 결과는 아닙니다.
- 오늘 급식 카드에 자료가 없으면 `오늘 급식 자료가 없습니다.`로 표시합니다. 나이스 요청에 실패하면 연결 오류 안내도 나옵니다.
- 달력 등 Streamlit 기본 요소의 일부 글자는 영어로 나올 수 있습니다. 이 앱에는 별도의 달력 입력 기능이 없습니다.
- Streamlit의 HTML 안 SVG 제거와 CSS 안 꺾쇠 처리 문제를 피하려고 로고는 CSS로 그렸습니다. `style.css`의 `.brand-mark`에서 달력 모양을 만듭니다.
